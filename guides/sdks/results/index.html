Reading Results

Checks keep a record of what has happened to them. This guide shows how to read it with the Go SDK, and assumes a client and ctx as created in Authentication.

There are three records for an uptime check, each answering a different question:

MethodAnswers
ListUptimeTestHistoryWhat did each individual test see?
ListUptimeTestPeriodsWhen was the check up, and when was it down?
ListUptimeTestAlertsWho was told, and when?

Pagespeed checks record their measurements with ListPagespeedTestHistory.

History​

Every time a check runs from a location the result is recorded: when it ran, where from, what status code the target answered with and how long it took, in milliseconds.

Recent tests of a check
res, err := client.ListUptimeTestHistory(ctx, id).
  Limit(50).
  Execute()
if err != nil {
  return err
}

for _, result := range res.Data {
  var took int64
  if result.Performance != nil {
    took = *result.Performance
  }

  fmt.Println(result.Created.Format(time.RFC3339), *result.Location, took, "ms")
}

Several fields are pointers because they are absent when the target did not answer at all. Check them before dereferencing.

Periods​

History is detailed, but it is a poor way to answer "how long was it down?". For that, read periods, each of which is a stretch of time during which the check had one status.

Downtime over the last week
week := time.Now().AddDate(0, 0, -7)

res, err := client.ListUptimeTestPeriods(ctx, id).
  After(week.Unix()).
  Execute()
if err != nil {
  return err
}

var down time.Duration
for _, period := range res.Data {
  if period.Status == statuscake.UptimeTestStatusDown && period.Duration != nil {
    down += time.Duration(*period.Duration) * time.Millisecond
  }
}

fmt.Println("down for", down)

A period's Duration is in milliseconds. A period that is still going on has no Ended time.

caution

Periods are selected by when they began. A period that began before After but was still going on at that time is not returned, so the total above can be a little short if the check was already down when the week began. To be exact, keep reading back until you reach a period that began at or before the start of your window, and clip it to the window.

Alerts​

Alerts are the notifications that were sent when a check changed status.

Alerts in the last day
day := time.Now().Add(-24 * time.Hour)

res, err := client.ListUptimeTestAlerts(ctx, id).
  After(day.Unix()).
  Execute()
if err != nil {
  return err
}

for _, alert := range res.Data {
  fmt.Println(alert.ID, alert.Status, alert.StatusCode)
}

Pagespeed History​

A pagespeed check records the load time in milliseconds, the size of the page in kilobytes and the number of requests it made.

Pagespeed measurements
res, err := client.ListPagespeedTestHistory(ctx, id).
  Limit(30).
  Execute()
if err != nil {
  return err
}

for _, result := range res.Data {
  fmt.Printf("%s %dms %.0fkb %d requests\n",
    result.Created.Format(time.RFC3339), result.Loadtime, result.Filesize, result.Requests)
}

Choosing a Window​

Each of these methods takes Limit, Before and After. Before and After are Unix timestamps in seconds, which is what time.Time.Unix returns. Results are newest first. See Pagination for reading further back than a single response.
